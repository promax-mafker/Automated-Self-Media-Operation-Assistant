# T05 · 选题与爆款对标

- 批次：3
- 依赖：T01 已合并；T02 已合并（`post` / `metric` 的真实数据流）
- 能力：选题策划、爆款对标分析

## 1. 目标

从「热榜信源 + 对标账号作品库」里算出**这周该做的 10 个选题**，每个选题卡都带可核对的对标证据：

- 3 个信源适配器：热榜 JSON（DailyHotApi 兼容形状）、RSS、本地 fixture；全部可离线。
- 对标分析：从对标账号近 90 天作品里提取「爆款共性」（时长区间、标题句式、话题标签、发布时段、内容类型）。
- 打分模型：`heat`（信源热度）+ `fit`（与自己的定位/历史表现契合）+ `benchmark`（对标共性命中）+ `timing`（时效衰减），加权成 `score`，四部分写进 `score_parts`。
- 产出 `topic` 行：`title / angle / hook / score / score_parts / evidence[]`。

## 3. 非范围

- 不联网抓取（真实 HTTP 实现要有，但测试只用 fixture；`--offline` 默认开）。
- 不做图片/视频里的内容理解。
- 不生成文案（那是 T06）；选题卡只给标题、角度、钩子。
- 不改 `topic` 表结构。

## 4. 契约要点

- `SourceAdapter.fetch(since=...)` 返回 `RawItem`（ADR §6.4）；每个适配器 `name` 固定为 `hotlist` / `rss` / `local`。
- 对标共性提取（`benchmark.py`）：
  - 用 `post` + 最新 `metric` 算每条作品的 `burst = views / P50(同账号 views)`；
  - 取 `burst >= 1.5` 的 Top 10% 作为「爆款集」，统计其时长中位区间、标题长度区间、高频标签（jieba 关键词 Top 10）、发布时段分布、内容类型占比；
  - 输出 `BenchmarkProfile`，写进 `topic.score_parts.benchmark` 供解释。
- 打分必须**确定性**：同输入两次运行 `score` 完全一致（不要用随机数、不要用 LLM 打分）。
- `timing` 用半衰期公式：`0.5 ** (age_hours / 36)`，`since` 缺失按 0 处理。
- `--input platform=xhs --input count=10 --input offline=1`；`evidence` 至少 3 条，`kind` 取 `hotlist|rss|post`，`ref` 必须是真实存在的 id 或 URL。
- 同一 `(platform, source_ref)` 重复导入要更新而非重复插入（`topic` 表没有唯一索引，用 `repo` 层先查后写）。

## 5. 验收标准

1. `wb topic suggest --platform xhs --count 10 --offline 1 --out /tmp/tp` → 产出 `topics.json`，恰好 10 条，全部有 `score_parts` 四个键与 ≥3 条 evidence。
2. 两次运行 `topics.json` 的 `score` 序列一致（测试断言 `==`）。
3. `wb topic benchmark --account demo_bench_a` 输出对标画像：爆款集的时长区间、标题长度区间、Top5 标签、时段分布，且每项带样本数。
4. 空信源（fixture 为空数组）→ 返回 0 条并提示「信源无新内容」，退出码 0，不抛异常。
5. 时效衰减：构造 age=0 / 36h / 72h 三条，断言 `timing` 约为 1.0 / 0.5 / 0.25（误差 < 0.01）。
6. `pytest -q` 覆盖：三个适配器的解析（含字段缺失的容错）、爆款集阈值、打分确定性、空信源、衰减公式。
7. 对标数据全部虚构（`demo_bench_*` 账号，作品文案是占位文本），不得出现真实博主。
