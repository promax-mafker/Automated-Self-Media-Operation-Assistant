# T01 · 骨架与 pipeline 内核

- 批次：1（单独派，后续全部 Ticket 从它开工作区）
- 依赖：无
- 目标是让后面 8 张工单能在同一套骨架上并行施工，互不碰文件。

## 1. 目标

交付一个可安装、可测试、可运行的 Python 项目骨架：

- `wb` 命令能跑；`wb doctor` 能看到环境与流水线覆盖情况。
- SQLite 迁移按 ADR §5 建好全部 10 张表 + FTS5 表。
- stage 注册表 + 流水线 runner 能跑通一条 `demo` 流水线，产出落库、落盘、可复算。
- 模型层有 `stub` 与 `openai` 两种实现，`stub` 能对任意 pydantic schema 生成合法值。
- 适配器协议（信源/知识库/渲染/视频/发布）定义好，缺实现时返回 Null 实现并 warning，不崩。

## 3. 非范围

- 不做任何真实业务流水线（`review`/`topic`/`copy`/`visual`/`video`/`pack` 的 stage 全部留空，`wb doctor` 标 `missing`）。
- 不做 Web 界面、不做渲染、不做视频、不做知识库。
- 不改 `assets/fonts/`、不改 `docs/adr/`、不改 `tickets/`。

## 4. 契约要点（按 ADR 实现，不要自创）

- ADR §5 的 DDL 逐字实现到 `store/db.py` 的迁移列表；重复执行幂等（`wb db init` 跑两次不报错）。
- ADR §6.1 的 `RunContext` / `Stage`；§6.2 的 `PIPELINES` 常量；§6.3 的 `LLMClient`；§6.4 的五个协议 + `get_*` 懒加载工厂；§6.5 的环境变量。
- `workbench/stages/__init__.py` 用 `pkgutil.iter_modules(__path__)` 导入同包模块（导入失败要提示是哪个模块、什么异常）。
- `workbench/cli_ext/__init__.py` 提供 `iter_subcommands() -> list[typer.Typer]`，`cli.py` 把它们挂到根命令上；后续 Ticket 只需新增文件。
- `store/repo.py` 提供每张表的 `insert_*` / `get_*` / `list_*` 最小集合，JSON 列传 dict/list 出去。

## 5. 验收标准

1. `bash scripts/setup.sh` 成功（走 `-i https://pypi.tuna.tsinghua.edu.cn/simple`；venv 不可用时退回 `python3 -m pip install --user -e .` 并打印提示）。
2. `bash scripts/check.sh` 全绿：`ruff check .` 无错、`pytest -q` 全过。
3. `wb doctor` 输出包含：
   - `WB_HOME` 绝对路径、SQLite 路径、`user_version`
   - 当前 LLM 模式（`stub` / `openai`）与 model
   - 7 条流水线（`review topic copy visual video pack demo`）的 stage 覆盖表：`demo` 全 `ok`，其余 `missing`
   - 退出码 0
4. `wb run demo --out /tmp/wbdemo` 成功，且：
   - `/tmp/wbdemo/manifest.json` 存在，含 `run_id`、`pipeline=demo`、5 个 stage 的结果
   - `/tmp/wbdemo/report.md` 存在且非空
   - 库里 `job` 表有 5 行 `status='done'`，`copy_set` 有 3 行，`asset` 有 1 行（fake PNG 用 `pillow` 画一个 1080×1440 纯色块，或写一个 1×1 PNG 也可，但必须是真实可打开的 PNG）
   - 重复跑一次得到新 `run_id`，行数翻倍（runner 不做幂等合并，幂等由各 stage 自己负责）
5. `wb run review` 在未实现时给出清晰错误：`MissingStage: review/metrics_import 尚未实现（T02）`，退出码 2，且 `job` 表留一行 `failed`。
6. 测试通过项必须包含：
   - 迁移幂等（两次 init 的 `user_version` 一致、表数一致）
   - `repo` 三类 CRUD（account/post/metric；JSON 列往返）
   - `runner` 失败路径：stage 抛异常 → `job.status='failed'` 且 `error` 有内容
   - `StubLLM.json()` 对一个嵌套 schema（含 `list[str]`、`int`、`bool`、嵌套模型）生成合法值，且 `model_validate` 通过
   - 离线断言：`tests/conftest.py` 的 autouse fixture 禁掉 socket，全部测试在此约束下通过
