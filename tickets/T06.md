# T06 · 五类文案生成与合规闸门

- 批次：3
- 依赖：T01（`LLMClient`、`copy_set` 表、`contracts.KB`）；T03 已合并（真实 KB）；T05 已合并（真实选题卡）
- 能力：多类型文案生成

## 1. 目标

一次调用产出 **5 类 × 2 长度 = 10 条**可直接用的文案，并且每条都过两道闸门：知识库取证、合规检查。

| kind | 含义 | short（100 字内 / 15-30 秒口播） | long（400-800 字 / 60-90 秒口播） |
| --- | --- | --- | --- |
| `spoken` | 口播脚本（含镜头提示） | √ | √ |
| `note` | 小红书图文笔记正文 | √ | √ |
| `seed` | 种草/带货（卖点 + 异议处理） | √ | √ |
| `explain` | 知识科普/干货 | √ | √ |
| `hook` | 引流钩子（评论区话术 / 私信 / 标题党 5 连） | √ | √ |

## 2. 可写路径

```
workbench/copy/__init__.py
workbench/copy/schema.py           # pydantic 输出模型（每类一个）
workbench/copy/prompts.py          # 读取 prompts/copy/*.md，带版本号
workbench/copy/generate.py
workbench/copy/grounding.py        # 用 KB 检索结果给 prompt 灌注 + 校验引用
workbench/copy/lint.py             # 合规 + 引用校验
workbench/stages/copy.py           # stage: copy_generate, copy_lint
workbench/cli_ext/copy.py          # wb copy ...
prompts/copy/{spoken,note,seed,explain,hook}.md
data/compliance/absolute_terms.txt
data/compliance/sensitive_terms.txt
docs/copy.md
tests/test_copy.py
```

## 3. 非范围

- 不做润色/改写工具、不做「去 AI 味」类检测规避（`docs/adr/0002` 合规红线）。
- 不做视频脚本分镜（T07 只吃 `spoken` 的正文）。
- 不改 `copy_set` 表结构；`compliance` 里放 `{passed, hits[], checked_at}`。
- 不在测试里调用真实模型。

## 4. 契约要点

- 生成入口：`wb copy gen --topic <topic_id> --platform xhs --out /tmp/cp`；`--kinds spoken,note` 可裁剪；
  产出 `copies.json`（10 条）+ 每条写一行 `copy_set`（同一 run 内 10 行同 `created_at` 前缀）。
- prompt 文件结构：`front-matter`（`version/model/temperature/max_tokens`）+ 正文模板，模板里只允许占位符
  `{brief}`（选题卡 JSON）、`{evidence}`（KB 命中片段，最多 5 条）、`{brand}`（`data/kb` 里的品牌摘要，可选）。
- 输出 schema（`schema.py`）：所有 kind 共用 `title/hook/body/tags`，`spoken` 额外 `shots: list[str]`（镜头提示），
  `hook` 额外 `variants: list[str]`（≥5 条）。字段缺失 → `ValidationError` 要转成带 kind 的清晰错误。
- 取证校验（`lint.py`）：
  1. 正文里出现的**数字**（价格、百分比、天数、人数）必须在 `evidence` 里能找到同数字，否则 `passed=false`；
  2. 命中 `absolute_terms.txt` 即 `passed=false` 并给出替换建议（同目录 `source: target` 映射行）；
  3. 命中 `sensitive_terms.txt` 标记 `needs_human=true`。
  4. `passed=false` **不阻断**落库（人要能看见问题），但 CLI 退出码为 3，便于脚本判断。
- `prompt_version` 记录 `prompts/copy/<kind>.md` 的 `version` + 文件 sha256 前 8 位。

## 5. 验收标准

1. `WB_LLM=stub wb copy gen --topic <id> --out /tmp/cp` → `copies.json` 10 条，`copy_set` 落 10 行；
   每类 × 每长度的 `kind/length` 组合齐全且不重复。
2. `wb copy gen --kinds note --out /tmp/cp2` → 2 条（short+long）。
3. 合规：把「全网最低价」写入一条 fixture 文案 → `lint` 命中 `absolute_terms`，`compliance.passed=false`，退出码 3，且输出给出替换建议。
4. 取证：`evidence` 为空但正文含 `99 元` → 命中「数字无出处」，`passed=false`。
5. 真实模型路径：`WB_LLM=openai` 且有 key 时能跑通（不在 CI；用 `pytest.mark.skipif` 跳过）。
6. `pytest -q` 覆盖：10 条组合齐全、缺字段错误、极限词命中、数字无出处、`--kinds` 裁剪、prompt 版本号写库。
7. 5 个 prompt 文件都有 `version`，且 `docs/copy.md` 里列出「改 prompt 的流程」。

## 6. 交付物

上列代码 + 5 个 prompt + 2 个词表 + `docs/copy.md`（每类文案的结构要求、取证与合规规则、如何加一类新文案）。PR 里贴 stub 模式下 10 条文案的 `kind/length/title` 一行摘要。
