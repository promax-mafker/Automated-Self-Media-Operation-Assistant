# T09 · Web 控制台 + 一键 demo + README

- 批次：4
- 依赖：T02-T08 全部合并（要有真实数据与产物可展示）
- 能力：工作台（把六条流水线串成一个人日常用的界面）

## 1. 目标

把这个仓库从「一堆命令」变成「一个人每天会打开的工作台」：

- `wb serve` 起一个本地控制台（默认 `127.0.0.1:8077`），6 个页面：
  概览 / 选题池 / 文案 / 素材 / 发布包 / 知识库问答。
- 每个页面读真实 `store` 数据；空态给出「下一步该跑哪条命令」的引导。
- `scripts/demo.sh` 离线一键跑通 `热点 → 选题 → 文案 → 海报 → 短视频 → 发布包 → 周报`，产物落 `out/demo-<时间戳>/`。
- README 30 行内讲清：这是什么、怎么装、怎么 5 分钟看到效果、边界在哪。

## 3. 非范围

- 不引入前端构建（无 Node、无 npm、无 Tailwind 编译）；HTMX 用本地文件 `workbench/web/static/htmx.min.js`（若不方便取，就用原生 form + 整页渲染，功能优先）。
- 不做登录、不做多用户、不做权限。
- 不做 WebSocket 实时进度；长任务在终端跑，页面只读结果。
- 不重写业务逻辑：页面只调 `repo` 与 `pipeline.runner`。

## 4. 契约要点

- 路由（固定路径，测试按此断言）：
  | 路径 | 内容 |
  | --- | --- |
  | `GET /` | 概览：本周发布数、播放中位数、Top3 选题、待发布包数、最近一次 job 状态 |
  | `GET /topics` | 选题池表格（分数、来源、状态），可点「生成文案」提交到 `POST /topics/{id}/copy` |
  | `GET /copies` | 文案列表（kind/length/title/compliance 徽标），点开看全文与引用 |
  | `GET /assets` | 素材网格（缩略图用 `<img>` 指向本地文件路由 `GET /files/<path>`） |
  | `GET /packs` | 发布包列表（状态、平台、时间），点开看 manifest |
  | `GET /kb` + `POST /kb/ask` | 知识库问答，返回命中片段与分数 |
  | `GET /files/{path:path}` | 只允许 `WB_HOME` 下的相对路径，越界返回 404 |
- 所有写操作走 `POST` + 表单 + 303 重定向（无 JS 也能用）。
- `scripts/demo.sh`：`set -euo pipefail`，用 `WB_HOME=out/demo-<ts>/.wb` 隔离，最后 `echo` 出一张产物清单表；
  不依赖网络、不依赖 LLM key（`WB_LLM=stub`）。
- `scripts/verify.sh`：跑 `check.sh` + `demo.sh` + `wb doctor`，任一失败非 0。

## 5. 验收标准

1. `wb serve --port 8077` 能起（后台），`curl -s localhost:8077/ | head` 返回 HTML 含「概览」。
2. `tests/test_web.py` 用 `fastapi.testclient.TestClient` 断言 7 个路由全部 200，且首页含关键数字/文案；`/files/../../etc/passwd` 返回 404。
3. 空库启动（全新 `WB_HOME`）时 6 个页面都 200，且页面里有「先跑 `wb run demo`」之类的引导文案。
4. `bash scripts/demo.sh` 从零跑通，退出码 0，`out/demo-<ts>/` 下有：`wb.sqlite3`、`packs/`、`artifacts/`、`report.md`、`topics.json`、`copies.json`、至少 1 张 PNG、至少 1 个 MP4。
5. `bash scripts/verify.sh` 退出码 0；故意让某条命令失败（例如 `WB_LLM=bogus`）时退出码非 0。
6. README 覆盖：一句话定位、能力 ↔ 命令表、5 分钟快速开始、边界与合规红线（不抓取/不自动发布）、目录结构、如何换模型。
7. `pytest -q` 覆盖：路由 200、空态、路径穿越 404、`/kb/ask` 无命中、demo 脚本的产物清单函数（把 shell 里的清单逻辑抽成 Python 可测函数更好）。
