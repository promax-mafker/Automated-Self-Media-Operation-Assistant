# T03 · 知识库（FTS5 + jieba + 引用）

- 批次：2
- 依赖：T01 已合并（`contracts.KB`、`kb_doc`/`kb_chunk`/`kb_fts` 表、CLI 自动挂载）
- 能力：知识库（供文案与选题取证的底座）

## 1. 目标

把「品牌资料 / 产品信息 / 历史爆款 / 常见问答」变成可被文案引用的检索层：

- 导入 md / txt（目录或单文件），按标题切块，落库 + 建 jieba 分词的 FTS5 索引。
- 提问返回 3-5 条命中片段：文档标题 + 小节标题 + 命中词 + 片段正文。
- 提供离线评测：20 条问答对，recall@3 ≥ 0.7 才算过。

## 2. 可写路径

```
workbench/knowledge/__init__.py
workbench/knowledge/build.py        # 必须提供 build_kb(cfg) -> KB（名字见 contracts.py 的懒加载工厂）
workbench/knowledge/chunk.py
workbench/knowledge/index.py
workbench/knowledge/answer.py
workbench/stages/kb.py              # stage: kb_ingest, kb_ask（后者可选）
workbench/cli_ext/kb.py             # wb kb ...
data/kb/seed/*.md                   # 5-8 篇虚构品牌资料
data/kb/eval.jsonl                  # 20 条评测
docs/kb.md
tests/test_kb.py
```

## 3. 非范围

- 不做向量检索、不引入 embedding 依赖、不做 PDF（`pypdf` 不在预置依赖里）。
- 不做多用户权限、不做增量更新以外的运维功能。
- 不改表结构；`kb_doc.meta` 里可放 `tags`。

## 4. 契约要点

- 切块：按 Markdown 标题层级切，单块 300-800 字；超长段落按句号切；块内保留 `heading` 路径（如 `产品/价格`）。
- 索引：`kb_fts(chunk_id UNINDEXED, seg)`，`seg` 是 `jieba.cut_for_search(text)` 用空格连接的结果；
  查询同样先分词，用 `MATCH '词1 OR 词2 ...'`，排序用 `bm25(kb_fts)` 升序（bm25 越小越相关）。
  **注意**：不要用 `tokenize='trigram'`，它对 2 字中文词无效（ADR §3 已记录）。
- 去重：`kb_doc.sha256` 相同则跳过（幂等），重复 `add()` 不产生重复块。
- 引用对象：用 `workbench/contracts.py` 里的 `KBHit`（字段以该文件为准：`doc_id / chunk_id / title / body / heading / score`）；`score` 归一化到 0-1（越大越相关）。
- `build_kb(cfg)` 失败要抛 `Unavailable`，上层会降级为 NullKB。
- `wb kb ask "问题" --k 5` 输出人可读表格 + `--json` 输出结构化。

## 5. 验收标准

1. `wb kb add data/kb/seed` → 输出 `docs=7 chunks=N`；再跑一次 `docs=0 skipped=7`（幂等）。
2. `wb kb ask "客单价怎么解释"` 返回 ≥ 3 条命中，每条带 `doc_title` / `heading` / `score` / 80 字片段。
3. `wb kb eval` 跑 `data/kb/eval.jsonl`，输出 `recall@3=0.xx (>=0.70)` 且退出码 0；故意把阈值调到 1.0 时退出码非 0。
4. 空查询 / 单字查询 / 命中为空：返回空列表 + 提示，不抛异常。
5. `pytest -q` 覆盖：切块（长段落、无标题、多级标题）、分词索引命中、幂等导入、评测脚本的通过/失败两条路径。
6. seed 资料是虚构品牌（`demo_` 前缀），不得含真实公司名或真实价格。

## 6. 交付物

上列代码 + seed 资料 + 评测集 + `docs/kb.md`（切块规则、分词与打分口径、评测方法、如何换成自己的资料）。PR 里贴 `wb kb eval` 输出。
