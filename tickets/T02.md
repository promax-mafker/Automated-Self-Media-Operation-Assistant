# T02 · 账号数据复盘与周报

- 批次：2
- 依赖：T01 已合并（表结构、repo、pipeline、CLI 自动挂载都可用）
- 能力：数据复盘与账号洞察

## 1. 目标

把平台导出的作品数据变成一份能指导下一周动作的周报：

- 导入 CSV（自己账号 + 对标账号），列名用映射表适配不同平台导出格式。
- 算出 8 个以上指标，按内容类型 / 发布时段 / 时长分组。
- 找出异常作品（z-score ≥ 2 或 ≤ -2）。
- 给出 3 条**引用具体数字**的下一步动作。
- 产出 Markdown 周报，同时把结论落库（`post` / `metric` / `account`）。

## 3. 非范围

- 不抓数据、不调平台 API、不做图表图片（周报是 Markdown 表格）。
- 不做大盘对标（那是 T05 的事）。
- 不改 `store/db.py` 的列；`raw` 列用来存平台原始行。

## 4. 契约要点

- `metrics_import`：`--input csv=<path> --input account=<handle>`；CSV 必须有列映射（见 `docs/metrics.md`），
  缺列时给出「缺哪列 + 支持哪些别名」的错误，不要静默跳过。
- 指标口径（写进文档，报表里必须与文档一致）：
  - `views` 中位数 / P90、`interaction_rate=(likes+comments+saves+shares)/views`、
    `save_rate=saves/views`、`follow_rate=follows/views`、`completion_rate` 均值、
    `burst_ratio=views/P90(同账号历史)`（爆款率）、发布量、`publish_gap`（发布间隔中位数）。
  - 分组维度：`content_type`、发布时段（4 段：早/午/晚/深夜）、`duration_sec`（≤15s / 15-30 / 30-60 / >60）。
  - 样本量 < 3 的分组必须在表里标 `样本不足`，不得参与结论推荐。
- `review_report`：`--input account=<handle> --input week=<YYYY-Www>`；周报结构固定五节：
  概览 / 指标表 / 分组对比 / Top5 与 Bottom5 / 下周三条动作。动作必须是「做什么 + 依据哪个数字」。
- 时间一律按 `WB_TZ` 归周（ISO 周）。

## 5. 验收标准

1. `wb review import --csv data/seed/metrics_sample.csv --account demo_xhs` 成功，输出 `imported=30 accounts=3`（数字以 seed 实际为准）。
2. 再跑一次同命令：按 `(post_id, captured_at)` 幂等，不产生重复行；输出 `skipped=N`。
3. `wb review week --account demo_xhs --week 2026-W45 --out /tmp/rev` 产出 `/tmp/rev/report.md`：
   - 五个二级标题齐全
   - 指标表 ≥ 8 行
   - Top5/Bottom5 各 5 行，带 `views` 与 `interaction_rate`
   - 三条动作每条含至少一个数字与一个作品 id 或分组名
4. 缺列 CSV：`wb review import --csv /tmp/bad.csv` 退出码 2，stderr 指明缺失列与支持的别名。
5. `pytest -q` 覆盖：周计算、指标计算（用手算 fixture 对 3 个数字）、分组「样本不足」分支、幂等导入、缺列报错。
6. `data/seed/` 里的账号名全部是虚构（`demo_` 前缀或带「（虚构）」）。
