为什么不是「再装五个工具」

做内容的人不缺工具，缺的是一条能复算的链路。拼装现成平台能跑，但三件事会一直疼。

口径不一致

选题看热榜、文案靠印象、复盘看平台后台，三处的「好」不是同一个标准，下周照样凭感觉。

→ 统一成一张表：指标口径写进文档，周报与选题打分共用同一份数据。

数据回不来

发出去就断了。作品数据躺在不同平台，导出格式各不相同，能用的只有手抄的几张截图。

→ 导入平台导出 CSV，按 URL 幂等回灌，复盘直接读本地库。

每一步都要重来

选题、写稿、排版、出图、剪视频、发布、记录，七个动作七种工具，每次从零开始。

→ 每步都是可单独调用的 stage，产物落盘落库，换素材不用换流程。

七项能力，六条流水线

每一条都能单独跑，也能接上前一条的产物。命令行是主入口，控制台是只读视图。

5 分钟跑起来

只需要 Python 3.10+。依赖走清华镜像（本机代理下 PyPI 直连会 SSL 中断）。

git clone https://github.com/promax-mafker/Automated-Self-Media-Operation-Assistant
cd Automated-Self-Media-Operation-Assistant

bash scripts/setup.sh        # 建 .venv，pip install -e ".[dev]"
wb doctor                    # 环境、数据库版本、各流水线的 stage 覆盖

bash scripts/demo.sh         # 离线跑通全链路，产物在 out/demo-<时间戳>/
WB_HOME=out/demo-<时间戳>/.wb wb serve --port 8077
                             # 打开 http://127.0.0.1:8077/

bash scripts/verify.sh       # ruff + pytest + demo + doctor，任一失败即非 0

接真实模型只改环境变量：WB_LLM=openai、WB_LLM_BASE_URL（任意 OpenAI 兼容端点）、 WB_LLM_API_KEY、WB_LLM_MODEL。不设 key 时自动走 stub，全链路仍可离线跑。

为什么不用现成的开源平台拼

调研过一圈，三条主流路线都被否掉，理由写在这里，方便你复核。

AiToEarn

最接近「开源版获客工作台」，但平台授权默认走官方 Relay，且官方不接受外部 PR——数据流与改造都不受控。

留作将来的 Publisher 适配器。

Coze Studio / RAGFlow

部署与加固成本高于本项目全部业务代码。三万字以内的知识库，SQLite FTS5 就够。

知识库超过 500 篇或需要多模态时再考虑。

poster-design / MediaCrawler

前者 AGPL，对外提供服务有传染风险；后者明确禁止商用，而「爆款对标」恰恰最想用它。

渲染用 Pillow 自绘；数据只导入平台官方导出。

边界写进代码，不只写在文档

  • 不抓取。没有爬虫、没有平台 API 调用；数据来自你自己导出的 CSV。
  • 不登录、不自动发布。发布只导出包并记录 URL，发不发由人决定。
  • AI 标识。发布包 manifest 固定 ai_generated: true，附可复制的声明话术。
  • 广告法闸门。极限词与敏感表述命中即标红，退出码 3，交人判断。
  • 字体与素材。只内置 Noto Sans SC（SIL OFL），不用来源不明的图片与 BGM。

已知限制

  • 「爆款对标」的证据强度，取决于你导入的数据质量。
  • 海报是声明式版式（文字、色块、列表），复杂设计需要换一个 Renderer。
  • 视频是卡片分镜，不做数字人与自动剪辑。
  • 单机单用户，没有多租户、权限与计费。
  • 默认走 stub 模型时，产物结构合法但内容是占位文本。

下一步（按性价比排）

  1. 接真实模型跑对比同一选题用两家模型各生成 10 条，人工盲评。
  2. 换 HTML/CSS 渲染加一个 Playwright Renderer，版式上限高一档，接口不变。
  3. 接半自动发布Publisher 接 social-auto-upload，默认 dry-run，账号风险自担。
  4. 多账号 / 多客户需要权限与数据隔离时，才考虑迁到 Coze Studio 这类底座。
